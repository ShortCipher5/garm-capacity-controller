# Fresh native-owner preparation contract

`capacity-native-prepare --source /absolute/root-owned/deployment-bundle` is an actual root-only staging helper. It does not install a systemd unit, enable/start a service, change host networking or storage, or qualify native activation. The native-owner activation guard is unchanged.

Input is a flat directory, never an archive, containing `manifest.json` and exactly the files named by `nativeprepare.ExecutableNames()` plus `capsule.json`, `owner-server.crt`, `owner-server.key`, `owner-client.crt`, `owner-client.key`, and `controller-ca.crt`. The manifest is `{ "version":"native-owner-preparation/v1", "id":"<64 lowercase hex>", "files": { "<fixed filename>":"<SHA256 lowercase hex>" } }`. Executables are the existing 17-command owner export plus this preparation helper. Each must be an actual ELF and at most64MiB; each private file at most1MiB; manifest at most16KiB; aggregate at most512MiB. No symlink, hardlink, unexpected entry, mutable non-root source, or alternate destination is accepted. Private source files must mode0600. Hashes must originate in the explicit trusted deployment recipe, not a caller-controlled browser proof.

The fixed existing root-owned parent is `/var/lib/garm-capacity-prepared`. A fresh exclusive `<id>` directory permanently consumes the request before copying. Failures leave it quarantined; they never clean up, retry, overwrite or adopt it. Successful files reside under `bin/` (0555) and `private/` (0600), inside0700 directories. All five control TLS paths in capsule JSON must name the corresponding final `private/` files. Other native/tool/image configuration still has to satisfy the real capsule checker.

Before a completion receipt, the helper executes only the exact copied/pinned owner executable with its existing read-only `--check-capsule-config --capsule-config <fixed-final-path>` mode, with a30s bound and no inherited environment, stdout or stderr. The checker validates the actual private configuration and certificate roles. It does not prove host support or activate anything. A manifest hash is not an executable trust root; the authenticated provisioning workflow must pin the helper and complete file manifest before transfer/execution.

The generated `garm-capacity-native-domain.service.staged` remains outside systemd's unit directories and has no Install section or writable-path grants. It names the actual guarded capsule command, but is deliberately not a qualified runtime unit. Do not install or enable it as a substitute for the missing qualified deployment contract.

Output and the durable receipt contain only version, ID, manifest/unit digests, `state=prepared_not_activated`, and `activation_authorized=false`. `--inspect <id>` rechecks the exact completed receipt and all staged hashes without execution. A lost acknowledgment permits only this inspection; a partial directory remains unknown and cannot be replayed. No secrets are included in errors/receipts. Root-malicious mutation/rollback and executable provenance outside the pinned deployment are not established by this helper.

The checker is launched through a fixed self-reexec child: only the pinned owner descriptor is retained as FD3; `close_range(CLOSE_RANGE_CLOEXEC)` marks FD4 and above for closure when executing the held owner. It never scans/closes the parent's descriptors. The actual checker gets a minimal fixed environment. Executable validation parses ELF64 little-endian headers and requires the helper's current amd64/arm64 machine, not magic bytes alone. This is not signature, dynamic-loader or full ABI qualification.

Transport implementations share `FileNames()`, `ManifestDigest(Manifest) (string,error)` and `ValidateReceipt(Manifest,Receipt) error`. Receipt validation derives the exact staged-unit digest at the fixed preparation destination. Do not accept an arbitrary success JSON or substitute a browser-provided file list.
