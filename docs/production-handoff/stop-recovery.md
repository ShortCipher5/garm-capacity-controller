# Operator stop and interrupted stock GARM recovery

**Production completion plan, not implementation or rollout authorization.** Baseline: [`fb8c39c26b865cc277783d8899af32dd63e6a836`](https://github.com/ShortCipher5/garm-capacity-controller/commit/fb8c39c26b865cc277783d8899af32dd63e6a836). Continues [#382](https://github.com/ShortCipher5/garm-capacity-controller/pull/382) and [#53](https://github.com/ShortCipher5/garm-capacity-controller/issues/53). Start with the code at the current target; this plan describes the gap, not a rewrite of Plan 02.

## Deliverable

An operator can stop new controller-initiated pool changes, see whether accepted work remains unresolved, and resume only when current ownership, the outcome of any accepted change, and the current desired settings are independently established. A stop acknowledgment means **no new controller work**; it does not mean that upstream work has completed, that a runner has stopped, or that capacity became available. GitHub continues to queue jobs and stock GARM continues to own runner creation, assignment and retirement. No fork, arbitrary GARM admin proxy, new credential grant, or direct settings database write. A local pause, a read-only diagnostic and a proven upstream resolution are three distinct capabilities.

## Phase A: implement and review offline now

1. Inventory the existing proposals and authenticated/read-only diagnostics. Reuse transition, reason and role contracts; separate three outcomes: local pause applied, local session drained, upstream outcome settled. Keep unknown state visible even while paused and after pause is lifted. Distinguish “not observed” from negative evidence and keep all write actions disabled in the stock-only build. Only wire status to an existing legitimate read-only owner path that can read the exact reviewed source/scope; do not expose arbitrary paths, credentials, raw journal rows, or a new externally callable command surface for writes.
2. In the existing local scheduler/control seam, serialize the pause acknowledgment against new admission to that controller's work. An unsubmitted proposal may be explicitly withdrawn; accepted or possibly accepted work must be held, never replayed or discarded. Missing or foreign lineage, stale evidence, failed writes/audit, restart with inflight work, and mismatch of expected scope are fail-closed. Confirm on restart that unavailable state never silently becomes a new writable journal. Do not change the upstream write plumbing or bind a new dispatch envelope to the journal, API or capacity ledger.
3. Specify operator behavior in the view and runbook: **Paused** blocks new work; **Unresolved** blocks apply and rollback even if local pause is lifted; **Read-only available** means diagnostics only; **Unavailable** is an explicit reason, not optimistic success. Acknowledgment, session drain and observed current settings must be rendered under different labels. Include only sanitized scope/result summaries in operator output; no secrets or unredacted request bodies. Verify the read-only mode still refuses all mutating methods.
4. Extend the disposable test plan to use the real protected managed read-only Service and existing topology contracts, not a fabricated success callback. Preserve bounded startup readiness waiting. Keep this independent of all real production writes and the other workstreams.

## Phase B: blocked until an independently qualified upstream contract exists

Before any settings writer or automatic recovery can be considered, review a supported stock-compatible interface for the exact installed build and scope. It must provide all of these properties concurrently:

- Exclusive authorized ownership of precisely the controlled fields, across controller replicas, native UI/CLI, delayed/queued requests, supervisors and other configured writers. Revoking credentials, terminating one client or draining its HTTP listener is insufficient for accepted work. Reviewer must enumerate all potential writers in the approved test topology.
- Independently authoritative result of the **exact original operation** after client failure/restart, plus a maintained guarantee that accepted work cannot settle later. Distinguish actual request causality from an authoritative current-state observation under a separately verified barrier. Neither old-value nor desired-value readback alone establishes causality. Do not guess from elapsed time, HTTP health, restart markers, or operator checkboxes.
- Fresh current fingerprint/generation and scope validation before re-entry, post-fence drift handling, and unrelated-field preservation. An inverse change is a newly reviewed action based on the proven current state; never replay or blindly restore historical settings. A completed settings change is still not release/teardown evidence.

If no supported interface proves these, record which claim failed, deliver the observe-only operator flow and leave mutation disabled. Do not add a new transport/dispatch design, token scope, direct database mutation, or fork to hide the gap. Implementing and enabling a qualified settings writer requires separate review and an authorized isolated test; no actions on production are assigned here.

## Acceptance matrix

| Case | Required result |
| --- | --- |
| Pause during new work / concurrent controller loops | No new work starts under the paused scope after acknowledged pause. Any earlier accepted or uncertain action remains unresolved and charged. Unrelated scopes neither inherit authority nor lose their own pause. |
| Restart after recorded proposal vs possibly accepted change | Pre-submit proposal retains explicit withdrawal path. Dispatched/unknown remains unknown with same operation and charges, even on a healthy new process. Wrong/missing/superseded journal or failed audit cannot reset the block. |
| Old or desired settings read back, stale/missing evidence, concurrent settings change | Can report observed value with freshness and drift; never resolves uncertain history, frees capacity or permits retry. Missing independent proof or stock-only adapter keeps write controls off. |
| Pause lift without fresh proof; rollback with drift | Lift only changes local pause state; unresolved action, changed scope/generation, and stale evidence still block apply. Rollback is not a replay and is unavailable unless both original outcome and current state qualify. |
| Protected read-only suspend and resume | A real entered handler must drain; timeout does not claim stopped. Old session remains revoked, first canceled resume exposes no replacement, and a successful explicit read-only resume reacquires the genuine authenticated session with unchanged lineage, charge and intents. No pool settings calls. |
| Resume succeeds but final independent restart validation or receipt does not | No completed receipt; unresolved intent remains visible. Any listener is diagnostics only. No write re-entry; a resume hook marker is never current topology evidence. |
| Qualified external adapter, if ever available | Test-only interruption, delayed completion, concurrent writer refusal, independently verifiable disposition and restart/rollback while authority is held. Validate on the exact candidate/installed version and publish sanitized evidence. If a property cannot be demonstrated, keep that adapter disabled. |

## Interfaces and release gates

- **Shared-cap enforcement** consumes the pause/unresolved/readiness verdict as a veto. It must not treat a missing verdict or historical receipt as permission, nor grant another writer access. **Safe runner-slot reuse** alone owns the question of releasing charge. **Per-job resource monitoring** can proceed independently and does not grant writes.
- Review/merge the offline implementation independently with all new runtime authority disabled. Separate evidence needed for installation-specific recovery from fixture success. Use normal candidate review and checks; don't merge this plan as proof of implementation.
- Production activation requires the supported adapter, independent proof of exact-stock operation settlement and late-writer exclusion, isolated qualification, then explicit staged rollout authorization. On doubt, stop new controller work and keep existing charges and unknowns. Roll back to the observe-only build without replacing or rewinding the journal; if compatibility is uncertain, keep it intact and the writer disabled.
