# Source evidence for exact-job runner metrics

**Stock per-job CPU, RAM and disk usage remains unavailable.** GitHub can identify a job and its assigned numeric runner registration. GARM can report the registration on one scoped running row. The inspected interfaces supply neither the original provider allocation linking that row to an immutable Incus incarnation nor an independent boot ID and process-start tick value for that incarnation. CI Health can still show GitHub timing and the exact job link.

This record covers the interfaces exercised by repository fixtures at baseline `bcec648e354e002b660e1dd919b31c27f088cddc`. The pins below are code and fixture versions. Installed versions, deployed permissions, capture cadence and collection overhead require a separate authorized qualification.

The measurement builder and display projection check CPU, RAM and disk capability separately. A RAM-only source can retain a measured RAM gauge while unsupported CPU and disk inputs remain omitted. If every supplied metric lacks support, the job has an explicit unavailable result.

The positive resource fixture supplies synthetic original-allocation and process-epoch facts. Removing either blocks collection and suppresses measurements before projection. The source-specific fixtures also cover foreign enrollment, revoked or expired receipts, incarnation and counter drift, absent counters and short or partially sampled jobs. [Identity negatives](../../internal/cihealth/attribution_claim_test.go) · [Scoped GARM reads](../../internal/garmapi/running_registration_test.go) · [Incus reads](../../internal/incusapi/runner_runtime_health_test.go) · [Usage fixtures](../../internal/cihealth/verified_usage_test.go)

**Activation remains blocked.** An authorized isolated qualification would need positive evidence for the missing allocation and process links, exclusive assignment covering the measured interval, and the installed sources' actual metric scope and cost. This change adds no live producer, periodic collection or usage-to-sizing input. [Monitoring scope](https://github.com/ShortCipher5/garm-capacity-controller/issues/268)
