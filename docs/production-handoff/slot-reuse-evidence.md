The finalization transaction requires the independent fence observation to follow the durable start of the current reconciliation epoch. The stored clock is a lower bound. A qualified adapter must wait for `BeginReconciliation` to return its committed barrier before collecting the new bounded inventory and observing the continuing fence. An observed terminal job or teardown can remain historical. Re-labeling a pre-barrier fence with the current epoch cannot fund release. The regression fixture proves refusal with the full charge and no tombstone, followed by release once with a fresh fence observation. It exercises the local transition with an offline source and provides no installed-stack qualification.

## Inventory and release-history limits

A new release currently requires exactly one inventory row across the ledger. Its full resource vector, deleting state, immutable scoped ID, host, pool and reservation must match the charged runner. Inventory records carry a route-dependent hash. The same physical UUID and generation can acquire a different hash after re-enrollment, so any second row keeps the candidate charged. This applies to linked, orphan and retained unknown rows on every host. Supporting release in a multi-runner inventory would require durable, independently authenticated physical identities for the other rows. Exact replay reads the original request tombstone and grants zero additional credit.

For a new eligible release, the writer transaction streams every prior retirement tombstone, verifies its digest and checks the stored physical identity. The work and time holding the SQLite writer lock grow linearly with release history. Admission and reconciliation writers can wait behind that scan. Before qualifying a production source, measure this contention at the largest supported history and admission load, or qualify an indexed identity lookup that preserves checks for all historical formats. Keep production release disabled until its writer-lock cost is bounded for that deployment.

The [slot-reuse handoff](https://github.com/ShortCipher5/garm-capacity-controller/pull/392) defines the installed-stack acceptance criteria.
