# New native server configuration

Use the existing Servers → Add an SSH server configuration section. Native registration has a separate preparation token and must be explicitly configured by the deployment administrator. It starts from an actual saved restricted inventory target, approved template/identity references, and a separately verified native administrator SSH target. Browser input never supplies private keys, arbitrary commands or filesystem paths.

Load the catalog/history, complete the paired connection and host identity, request a read-only review, then separately approve the exact permanent local identity reservation. Registration creates local private configuration and consumes the preparation/owner identities before materialization; unknown outcomes cannot be reset or replayed. Read history after uncertainty. A registered configuration is not a prepared server or runtime authority.

Then use actual discovery and saved resource selection. A target without an initial plan stays a distinct pending configuration. It can build a first real bundle following a successful never-attempted recovery observation. Explicitly approve that exact bundle as its initial local preparation plan. Only afterward use the separate preparation panel to review and authorize SSH transfer. No step here implicitly transfers files, installs software, enrolls capacity or activates runners.
