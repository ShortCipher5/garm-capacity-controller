# Saved discovery selection to runner mix

In the existing native planning panel, load a real saved selection and choose runner sizing. Enter an explicit per-runner disk allowance and request the proposal with the separate planning token. The server reopens the protected saved selection and checks freshness; the browser verifies the returned host, digest, expiry, guest CPU/RAM and disk choice. Proposal counts fit configured guest CPU/RAM only. Disk fit, actual capacity and runtime authority are not established.

Send the proposal to Profiles explicitly. Nothing is saved. A real configured ledger host must exist; no host is created from this draft. Read that host's current mix after receiving the proposal, explicitly import the values, edit if desired, then separately review and save with the management token and fresh ledger sequence/revision. Global profile replacement warnings still apply.

Expired imported proposals cannot be reviewed or saved. Request a fresh proposal, or discard the imported values to restore the actual saved mix. Changing proposals invalidates prior review; disconnect clears the in-memory transfer. No autosave, reservation, pool mapping, runner scaling or disk-fit claim is introduced.
