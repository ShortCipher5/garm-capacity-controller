# Native configuration planning in Servers

The existing server setup disclosure offers authenticated SSH discovery for a deployment-approved pairing of restricted inventory and native preparation destinations. Different addresses/ports are permitted only through that explicit binding; the UI does not infer shared host identity from IP equality. Its separate token is cleared after every request.

A real read produces a short-lived server-held proposal. The form uses the actual resource defaults, exposes system reserves and total/partition CPU, RAM and task limits, and warns when selected allocation leaves less than proposed headroom or exceeds observed available RAM. OS totals may describe a VM/container; no physical capacity or native authority is asserted. Storage identity/quotas and runner-size/repository policy remain separate configuration.

Saving sends only the selected numeric configuration and exact server review digest. It never sends caller-crafted inventory, credentials, paths, native endpoints or proof. The response must match the reviewed target, observation, expiry and every selected limit. The saved selection is input to the real bundle builder, not an applied host setting or prepared/activated host. Preparation remains separately reviewed. Expired selections require rediscovery.

Uncertain save responses clear executable review and never automatically replay. Operators can load the actual bounded saved-selection history before deciding what to do next. History is configuration evidence, not current applied state. Closing, changing target or disconnecting clears credentials/review and fences late responses. Hosted browser tests cover buffer warnings/configuration-only save and interrupted save; no local browser pass is claimed.

## Explicit local assembly and registry reload

A selected saved record can now open the actual deployment-configured assembly workflow on the same screen. Its separate native-preparation token loads current registered configuration and verifies the saved native destination against the returned public SSH identity, including the fingerprint of its pinned host key. A fresh selection and unconsumed preparation are required for building. The request carries only fixed target/selection identifiers; private files and output paths remain server-side.

Building a local private bundle does not upload or reload it. Its actual completion report must match the exact saved selection and target. Reload needs another explicit review of current registry review, new plan/manifest and assembly digest. The returned registry must match the reviewed assembly and remain not started. Actual SSH transfer still requires reloading the separate preparation panel and approving its exact transfer; this UI never issues that action. Consumed or uncertain preparation IDs cannot be replaced.

Unknown build outcomes offer inspection of the same completed selection, never automatic rebuild. Unknown reload requires reading current registry before another decision. Historical assembly inspection does not refresh OS observations or grant host authority. Closing, parent-selection changes, errors and unmounting discard executable review and credentials and fence late responses. Client tests cover correlation, pinned identities, exact request bodies and no retries. Hosted browser cases cover explicit build/reload without SSH and close-during-build; no local browser execution is claimed.

### Actual local recovery status

The selected-bundle panel can read the actual protected local assembly status: no prior attempt, consumed/unknown attempt with or without observed partial output, or a completed bundle re-opened and verified. A successful explicit `never_attempted` response is required before the UI offers build review. Unknown status never offers rebuild, deletion, reset or an active-worker claim. Unavailable, malformed, orphaned, changed or busy responses remain unavailable, not proof of no prior attempt. Completed metadata does not imply registry reload, SSH preparation, current resources or activation. Status is a user-requested read and does not create files or automatically poll or retry writes.
