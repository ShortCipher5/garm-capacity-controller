# Managed maximum-reduction view

The existing Garm settings page recognizes the server's `maximum_reduction_only: true` contract. This is a restricted managed-supervisor adapter, not generic write authorization or adoption of an existing stock installation.

Only an explicitly reviewed positive pool maximum strictly below the observed maximum and at least the unchanged idle minimum can be sent. The payload contains only `max_runners`. Zero/fully minimized pools have no available reduction. Enable/pause, priority, tags, idle minimum and repository-balancer controls are absent. These restrictions complement, not replace, server enforcement.

Changing management mode invalidates a draft like other remote settings drift. A generic review cannot be applied after switching into restricted mode. Pending/unknown journal blocks and unavailable observations remain blocking; the restricted adapter advertises no receipt-resolution endpoint and the browser does not replay or clear operations.

A confirmed maximum change is not evidence of runner retirement, drained resources, native execution readiness, or safe future increases. Existing-install discovery remains a separate non-adopting mode. Frontend tests use mocked response contracts; real supervisor/ledger integration belongs to the backend adapter's qualification.
